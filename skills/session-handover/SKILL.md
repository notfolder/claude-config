# session-handover

「セッションの引き継ぎ準備」を実行するスキル。**確認を取らずに実行する。**
cwd で書き先が変わる。2 つを混ぜない（二重管理にすると必ず食い違う）。

- **cwd == `$HOME`（ホーム）** → 下の「ホームの場合」。`~/docs/` に書く
- **それ以外（個別プロジェクト）** → 下の「プロジェクトの場合」。`<project>/.history/` に書き、`~/docs/` には書かない

## ホームの場合

1. **`~/docs/<YYYY-MM-DD>-session-handover.md`** に、**日付時刻**とそのセッションの
   作業内容（依頼内容・実行した変更・調査結果・意図的に残したもの・環境メモ）をまとめる。
2. そのセッションでユーザーが**強く指示した内容**を短く CLAUDE.md にまとめ、
   詳細は 1 を参照するように書く。書き先は `~/.claude/CLAUDE.md` 冒頭の「このファイルの役割」で振り分ける
   （全マシン共通なら `~/.claude/CLAUDE.md`、そのマシンだけなら `~/CLAUDE.md`）。
   **`~/.claude/CLAUDE.md` は公開リポジトリに入る。** 自宅の環境や開発中の作業に触れる指示は `~/CLAUDE.md` に書き、
   `~/.claude/CLAUDE.md` には `~/docs/` へのリンクを書かない（ほかのマシンではリンク切れになる）。
3. **`~/docs/<YYYY-MM-DD>-<HHMM>-<テーマ>-brief.md` を新規作成する。**
   **1 セッション 1 ファイル。既存ブリーフに追記・統合しないこと**（混ざるため）。
   末尾 `-brief.md` が目印で、フックはこれだけを拾う（調査まとめ等とは混ざらない）。
   中身は `# タイトル` / `更新:` / `詳細:`（1 のパス）/ `## 概要`（1 行だけ）/
   `## バックログ`。**`# タイトル`・`更新:`・`## 概要` はフックが読むので必ず入れる。**
4. **`~/docs/BACKLOG.md` を整理して書き出す**（下の「バックログ」節）。
5. 書いたパスを一覧で報告する。

調査や設計の詳細は `~/docs/<YYYY-MM-DD>-<テーマ>.md` に別ファイルでまとめる。
`~/docs` は git 管理外で、ブリーフと BACKLOG.md はそのマシンにしか無い。

## プロジェクトの場合

### 出力先

```
<project>/.history/<YYYY-MM-DD>-<HHMM>-<セッション概要>/
├── summary.md    … このセッションの概要（引き継ぎメモ + ブリーフを兼ねる）
└── session.md    … セッションの Markdown エクスポート（逐語）
<project>/.history/BACKLOG.md   … プロジェクトの残作業を集約（常に最新・手で書く）
<project>/CLAUDE.md             … ユーザーの強い指示を短く追記（無ければ作る）
```

- **1 セッション 1 ディレクトリ。既存ディレクトリに追記・統合しない。**
- `<セッション概要>` は空白なしの短い語（日本語可）。例: `2026-09-06-0328-qiita記事化`

### 手順

1. **`session.md` を書き出す。** 現在のセッション ID は scratchpad パスの UUID と一致する。
   ```
   python3 ~/.claude/skills/session-handover/scripts/session_export.py \
     --session <セッションID> --out <project>/.history/<dir>/session.md
   ```
   `--session` を省略すると、そのプロジェクトで最後に更新された `.jsonl`（＝現在のセッション）を使う。
   出力の `range` と `counts` を見て、期間と発言数が今のセッションと合っているか確認する。
2. **`summary.md` を書く。** 見出しは固定。`# タイトル` / `更新:` / `## 概要` の 3 つは
   SessionStart フック（`session-brief.py --history`）が次回起動時に 1 行表示に使う:
   ```
   # <タイトル>
   更新: <YYYY-MM-DD HH:MM TZ>
   セッション: <ID>
   ログ: ./session.md
   ## 概要        … 1 行だけ
   ## やったこと  … 依頼内容・実行した変更・調査結果・意図的に残したもの
   ## 決定事項    … ユーザーが決めたこと・強い指示（理由つき）
   ## 次にやること
   ## バックログ  … BACKLOG.md と同じ 3 状態で、このセッションに関わる項目
   ```
3. **`.history/BACKLOG.md` を整理する。** 全項目を見直し、増えた項目を足し、片付いた項目は
   `- [x] (日付)`、見送りは `- [-] (日付) … — 理由`。行は消さず状態だけ書き換える。
   テーマごとに `## 見出し` を立て、直下に `概要: .history/<dir>/summary.md` を書く。
4. **プロジェクトの `CLAUDE.md` に強い指示を追記する。ただし「毎回読む必要がある決まり」だけを
   1 項目 1 行で書き、経緯は `<project>/docs/rules/` に置く**（ユーザー指示 2026-09-24）。
   - **CLAUDE.md に残すもの（毎回読む必要がある決まり）**: 決まりの一文 + 出どころの日付 +
     経緯へのリンク。例: `- **数値の問いをヒアリングしない**（2026-09-11、[経緯](docs/rules/企画の進め方.md)）`
   - **`docs/rules/` に移すもの（必要なときにリンクを辿って読めばよい経緯）**: なぜその決まりに
     なったか、ユーザーの発言の引用、失敗の具体例、失った時間、当時の数字。テーマごとに 1 ファイル
     （例: `docs/rules/企画の進め方.md`）にし、見出しは CLAUDE.md の一文と同じ言葉にする。
     `docs/rules/README.md` にファイルの一覧と役割を書く。
   - **`CLAUDE.md` は 200 行未満に保つ**（ユーザー指示 2026-09-24）。追記のあと `wc -l` で測り、
     200 行以上なら、古い項目から経緯を `docs/rules/` に移して 1 行にする。
     PostToolUse フック `hooks/claude-md-lines.sh` が書き換え後に測って警告する。
     **このフックはこのスキルを起動したセッションでだけ鳴る**（ユーザー指示 2026-09-24）。
     整理は引き継ぎ準備のときにまとめて行う前提で、通常の編集では黙る。
   - 「場所」節の「最新は … その前は …」の連鎖は最新の 1 件だけ残す。履歴は `.history/` にある。
   - 無ければ作る。全マシン共通・全プロジェクト共通の指示なら `~/.claude/CLAUDE.md` へ。
5. **`~/docs/BACKLOG.md` には触らない。** 入口リンクも項目も書かない（ユーザー指示 2026-09-06）。
   ホーム側の一覧とプロジェクト側の一覧は完全に分ける。
6. 書いたパスを一覧で報告する。

### 注意

- **`.history/` は git に含めるが公開はしない**（`.gitignore` に入れない。ユーザー指示 2026-09-06、
  **2026-09-21 に「公開リポジトリでも公開する」から訂正**）。NDA 下の資料の内容・契約条件・
  取引先とのやり取りが入りうるので、**非公開リポジトリに置くもの**とし、公開リポジトリへ移すときは
  `.history/` を除外する。**住所などの個人情報も、書き出し後に伏せ字にする。**
  `session.md` にはツール結果を含めないが、ユーザー発言と Claude 本文にトークン・パスワード・
  非公開 URL が混ざっていることはある。書き出し後に `grep -n -i 'token\|password\|secret\|Bearer'`
  などで目視し、あれば伏せ字にしてから commit する。
- `session_export.py` は `~/.claude/projects/<cwd を英数字以外→'-' にした名前>/` を探す。
  cwd を変えて起動したセッションは別ディレクトリになるので `--cwd` で指定する。
- 途中で `/clear` したセッションは `.jsonl` が分かれる。前半も残したければ `--session` で
  それぞれ書き出す。

## バックログ

- **ホームは `~/docs/BACKLOG.md`、プロジェクトは `<project>/.history/BACKLOG.md` が、残作業を集約した常に最新の一覧。**
  ホーム側の対象はマシン環境・アカウント・どのプロジェクトにも属さない用事。
- **cwd に対応するものだけを読み書きする。** ホームから個別プロジェクトの BACKLOG を読みに行かない
  （リンクを辿って中身を会話で列挙するのも含む）し、書きにも行かない。逆も同じ。
  個別プロジェクトの残タスクは `~/docs/BACKLOG.md` に書かず、入口リンクも置かない（ユーザー指示 2026-09-06）。
- **越境する残作業に気づいたら、どちらのファイルにも書かず、ユーザーに報告して委ねる。**
  例: ホーム側の作業で生じた「あのプロジェクトの BACKLOG の状態が古い」。
- **自動生成しない。** 一度フックに生成させて差し戻された。フックは表示するだけで、
  整理・書き出しは引き継ぎ準備の作業として手で行う。
- **状態はチェックボックスで表し、行は消さず状態だけ書き換える。**
  - `- [ ] 内容` … 未実施（**フックが拾うのはこれだけ**）
  - `- [x] (YYYY-MM-DD) 内容` … 実施済み。完了日を残す
  - `- [-] (YYYY-MM-DD) 内容 — 理由` … 実施しないと判断した。判断日と理由を残す
- **引き継ぎ準備のときは必ず全項目を見直す。** 増えた項目を足し、片付いた項目と
  見送った項目は状態を書き換え、古い数字と日付を直す。
- 同じ内容をブリーフ（プロジェクトでは `summary.md`）の `## バックログ` にも書くので、**両方の状態を揃える。**
- 数字は測った日を添える。日付は絶対日付で書く。
- フックの表示（起動時と `/clear` のとき）は `hooks/session-brief.sh` → `session-brief.py`。
  最新のブリーフ（プロジェクトでは `summary.md`）を 1 行と、BACKLOG.md の `- [ ]` 行を `## 見出し` ごとに出す。
